# website / backend — Express + `node:sqlite` API

> **"KFM Group content API — Express over SQLite (`node:sqlite`)."** Two runtime dependencies.
> **No database server to install, no native module to compile** — SQLite is a file and its
> driver is inside Node.

**Parent:** [[KFM_GROUP/website/website|website]]
**Dev port** 4000 · **production on kerry** PM2 `kfmgroup-backend` :8098

---

## ⚠️ The hard requirement

**Node.js 22.5+.** `node:sqlite` is a Node **built-in with no fallback driver**. Measured
2026-09-22: it works on **v22.22.3** (prints an `ExperimentalWarning`) and throws
**`ERR_UNKNOWN_BUILTIN_MODULE` on v20.20.2**. The system Node on kerry is v20 and **cannot run
this at all**; production runs v22.22.3.

## Dependencies — deliberately four

| | Package | Why |
|---|---|---|
| runtime | `express ^5.2.1` | the server |
| runtime | `cors ^2.8.6` | cross-origin for the Next frontend |
| dev | `typescript ^7.0.2` | `tsc` → `dist/` |
| dev | `@types/*` (`cors`, `express`, `node ^26.6.2`) | types only |

ESM (`"type": "module"`). `dev`, `migrate` and `seed` all run TypeScript **directly** via
`--experimental-strip-types`; only `build`/`start` go through `tsc` and `dist/`.

## Source

| File | Responsibility |
|---|---|
| `src/server.ts` | The Express app — mounts the routes, serves `/api/health`. |
| `src/db.ts` | Opens `../data/kfm.db` through `node:sqlite`. |
| `src/migrate.ts` | Applies `migrations/*.sql`, recording each in `schema_migrations`. **Safe to re-run** — skips anything already applied. |
| `src/seed.ts` | Reloads `contracts` + `people` from `seed-data.ts`. **Safe to re-run** — it **never touches `contact_submissions`**. |
| `src/seed-data.ts` | The seed content: **7 contracts and 8 people**. Per decision #16, *nothing* about a contract or a person is hardcoded in a component. |
| `src/routes/contracts.ts` | `GET` contracts. |
| `src/routes/people.ts` | `GET` people. |
| `src/routes/contact.ts` | `POST` the contact form → `contact_submissions`. |

## Migrations

| File | What it creates |
|---|---|
| `migrations/001_init.sql` | The three tables — `contracts`, `people`, `contact_submissions` (+ `schema_migrations`). Full column detail in `docs/db_schema.md`. |

Only one migration exists. The schema was extended beyond the original plan (decision #16):
`contracts` gained `status`, `sector`, `summary`, `card_note`, `image_url`, `image_alt`;
`people` gained `photo_url`.

## Scripts

| Script | Does |
|---|---|
| `npm run dev` | Express on **:4000**, `--watch`, TypeScript stripped at runtime |
| `npm run build` | `tsc` → `dist/` |
| `npm start` | `node dist/server.js` |
| `npm run migrate` | applies `migrations/*.sql` |
| `npm run seed` | reloads contracts + people |

## Health check that means something

```bash
curl -s localhost:4000/api/health
# {"ok":true,"db":".../data/kfm.db","contracts":7,"uptime":…}
```

`/api/health` **runs a real query**, so a 200 proves the **database is reachable** — not merely
that the process started.

## ⚠️ Notes

1. **Start the backend first in development.** `/`, `/sectors` and `/people` read from this API
   and render an error page if it is down.
2. **`dist/` is build output** (11 `.js` + `.js.map` pairs). Regenerated by `tsc`; not indexed.
3. **`node_modules/` is vendored.** Not indexed.
4. **There are no tests.** Verification to date is the manual sweep in `docs/todo.md` Phase 9.
5. **There are no secrets in this project.** Environment variables are all optional —
   `docs/handover.md` §6.
